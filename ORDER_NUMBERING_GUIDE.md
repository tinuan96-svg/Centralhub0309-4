# CentralHub order numbering and payment flow

## Current boundary

Customer orders originate in MalluSpices, KeralaGrocery, PocketGrocery, or another connected storefront. CentralHub does not create customer orders directly. It receives store-originated orders through the inbound sync, displays them in the Order Queue, and manages fulfilment, payment confirmation, status, refunds, shipping, inventory, and outbound status updates.

The storefront or payment provider remains the source of the customer-facing order number. CentralHub must preserve that number when an order is imported.

## Payment workflow

- Storefront checkout creates the order and records its payment state.
- CentralHub imports the order and keeps its source identifiers.
- Staff may confirm or update payment for an existing imported order when required.
- Payment confirmation triggers the existing inventory and fulfilment rules, gateway-fee reconciliation, communication events, and store status update.
- No temporary order number is generated by CentralHub for a new customer order.

## CentralHub order responsibilities

- View and filter synced orders by store, payment state, fulfilment state, date, and customer.
- Run or retry inbound store synchronisation.
- Update status, cancellation, refund, shipment, and payment state for existing orders.
- Push permitted status and refund changes back to the originating store.
- Keep order status history, inventory movements, and reconciliation records auditable.

## Non-goals

The former manual order-entry flow, CreateOrderModal, and CentralHub create-order endpoint are intentionally disabled. Do not reintroduce them without an explicit architecture decision.
